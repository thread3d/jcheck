# J0467 — AmbiguousOverload

**Tier:** T2 flow · **Default level:** warn

## Why it matters

When one overload refers to another overload declared later in the same class, javac cannot always
tell which one a call means while the class is still being entered. The warning is the compiler
saying the resolution may change as the class grows, which is exactly the kind of thing that turns
into a surprising behaviour change later.

## Failing example

```java
class Printer {
    void print(String s, Object... rest) {
        print(s); // may resolve differently once the overload below is considered
    }

    void print(String s) {
        System.out.println(s);
    }
}
```

## Fixed example

```java
class Printer {
    void print(String s) {
        System.out.println(s);
    }

    void print(String s, Object... rest) {
        print(s);
    }
}
```

## Notes

- Declaring the more specific overload first is enough; no call sites change.
- Qualifying the call (`this.print(s)`) does not help, because the ambiguity is about which member
  is in scope during enter, not about the receiver.
- The warning appears when compiling with `-Xlint:all`; jcheck turns that lint group on by default.
