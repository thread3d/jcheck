# J0470 — LossOfPrecision

**Tier:** T2 flow · **Default level:** warn

## Why it matters

A compound assignment such as `intVar += longExpr` performs an implicit narrowing cast back to the
left-hand type, so the value can silently wrap or truncate. The error form of this check (J0252)
only fires when javac can prove a constant is too large; this warning fires for the general case.

## Failing example

```java
long delta = 5_000_000_000L;
int total = 0;
total += delta; // wraps to 705032704
```

## Fixed example

```java
long delta = 5_000_000_000L;
int total = 0;
total = Math.toIntExact(total + delta); // throws instead of truncating
```

## Notes

- The explicit-error sibling is J0252; both are in the `numeric-narrowing` group.
- Prefer `Math.addExact` / `Math.toIntExact`, or widen the variable to `long`, rather than casting
  back and hoping.
- Suppress with `@SuppressJcheck(code = "J0470", reason = "...")` when the wrap is the intended
  behaviour, such as a hash fold.
