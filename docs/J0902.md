# J0902 — TodoMarker

**Tier:** T3 (jcheck-checks) · **Default level:** warn

## Why it matters

`Todo()`, `Unreachable()` and `Unimplemented()` from jcheck-support throw at runtime with the
file and line that called them. They are useful while a branch is unfinished, but a marker that
reaches production is a crash with a stack trace. This check makes every unfinished branch
visible so none can ship silently.

## Failing example

```java
int fee(Plan plan) {
    return Todo(); // the pricing table is not finished yet
}
```

## Fixed example

```java
int fee(Plan plan) {
    return switch (plan) {
        case FREE -> 0;
        case PRO -> 990;
        case ENTERPRISE -> 9_900;
    };
}
```

## Notes

- If the work is genuinely deferred, put the tracked issue in the marker message and suppress
  with a reason: `@SuppressJcheck(code = "J0902", reason = "JIRA-4123")`.
- Replace `Unreachable()` with the exhaustiveness the type system already provides: a sealed
  switch with no `default` makes the impossible branch unrepresentable.
- The check is a warning so an unfinished branch does not block compilation; the strict profile
  promotes warnings to errors for release builds.
- `jcheck check --report-suppressions` lists any remaining markers so they can be triaged.
