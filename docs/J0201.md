# J0201 — NonExhaustiveSwitch

**Tier:** T2 (flow) · **Default level:** error

## Why it matters

A `switch` over a sealed type or an enum must handle every case, because adding a new subtype
or constant later has to fail to compile rather than silently fall into `default`. javac already
enforces this for switch expressions and pattern switches; this code names the case that is
missing so the fix is obvious.

## Failing example

```java
sealed interface Shape permits Circle, Rectangle, Triangle {}

record Circle(double r) implements Shape {}

record Rectangle(double w, double h) implements Shape {}

record Triangle(double b, double h) implements Shape {}

double area(Shape shape) {
    return switch (shape) {
        case Circle c -> Math.PI * c.r() * c.r();
        case Rectangle r -> r.w() * r.h();
    }; // Triangle is not handled
}
```

## Fixed example

```java
double area(Shape shape) {
    return switch (shape) {
        case Circle c -> Math.PI * c.r() * c.r();
        case Rectangle r -> r.w() * r.h();
        case Triangle t -> 0.5 * t.b() * t.h();
    };
}
```

## Notes

- A switch expression over a sealed type cannot be suppressed; the compiler requires
  exhaustiveness. If a case truly cannot occur, give it a `throw`-returning case rather than
  adding `default`, which would hide future subtypes.
- For a classic enum switch statement, add the missing constants and avoid `default`
  (Error Prone `MissingCasesInEnumSwitch` reports the same class of problem).
- Related: J0202 for pattern switches, and `UnnecessaryDefaultInEnumSwitch` when a `default`
  defeats the exhaustiveness check.
