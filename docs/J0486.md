# J0486 — ObsoleteSourceRelease

**Tier:** T2 (flow) · **Default level:** warn

## Why it matters

The JDK deprecates old `-source`/`--release` values and eventually removes them. `source value 8
is obsolete and will be removed in a future release` means the project's language-level floor is
older than the running JDK still recommends, so a future JDK upgrade will fail the build rather
than warn. Fixing the floor now is much cheaper than fixing it during a toolchain upgrade.

The warning has no source position: it is about the build, not about a file, so jcheck reports it
without a span.

## Failing example

A project pinned to a floor the running JDK has deprecated (here JDK 20 with `--release 8`, or
`maven.compiler.release=8`):

```xml
<properties>
  <maven.compiler.release>8</maven.compiler.release>
</properties>
```

```text
warning: [options] source value 8 is obsolete and will be removed in a future release
```

## Fixed example

Raise the floor to a release the running JDK supports:

```xml
<properties>
  <maven.compiler.release>17</maven.compiler.release>
</properties>
```

## Notes

- Companion warnings: J0487 names the obsolete `-target` value, and J0488 is javac's advice on
  silencing the pair with `-Xlint:-options`. All three appear together when the floor is old.
- Raising the floor is a source- and API-compatibility change; run the build before assuming the
  lower floor was gratuitous.
- When the old floor is deliberate (a published library's minimum), suppress the group with
  `-Xlint:-options` and pin the JDK, rather than treating the warning as noise.
