# J0476 — MissingDeprecatedAnnotation

**Tier:** T2 flow · **Default level:** warn

## Why it matters

Marking a declaration `@Deprecated` in its Javadoc but not with the annotation means tooling cannot
see it: the compiler will not warn callers, IDEs will not strike it through, and `-Xlint:removal`
cannot tell whether it is going away. The `-Xlint:dep-ann` lint exists to catch exactly this drift
between the comment and the annotation.

## Failing example

```java
/**
 * @deprecated use {@link #format} instead
 */
public String toText() {   // no @Deprecated annotation
    return "";
}
```

## Fixed example

```java
/**
 * @deprecated use {@link #format} instead
 */
@Deprecated
public String toText() {
    return "";
}
```

## Notes

- Add `since` and `forRemoval` to the annotation when the deprecation is real: `@Deprecated(since =
  "2.0", forRemoval = true)`.
- The annotation-without-Javadoc case is a separate concern; the compiler only warns about the
  reverse.
- Part of the `all` lint group jcheck enables; suppress with a reason if the declaration must stay
  unannotated.
