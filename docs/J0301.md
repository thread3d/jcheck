# J0301 — UncheckedArithmetic

**Tier:** T3 (jcheck-checks) · **Default level:** deny in `@Checked`

## Why it matters

Java `int` and `long` arithmetic wraps silently on overflow, so a size, offset or protocol value
can turn negative with no signal. Rust panics in debug builds and has `checked_add` in release;
Java's nearest equivalent is `Math.addExact` and friends. In `@Checked` code the custom pack
requires those helpers.

## Failing example

```java
@Checked
final class Frame {
    int nextOffset(int offset, int length) {
        return offset + length; // can wrap to a negative offset
    }
}
```

## Fixed example

```java
@Checked
final class Frame {
    int nextOffset(int offset, int length) {
        return Math.addExact(offset, length); // throws ArithmeticException on overflow
    }
}
```

## Notes

- The check is enabled only under `@Checked` on a class or package; plain arithmetic stays legal
  everywhere else.
- `Math.addExact`, `subtractExact`, `multiplyExact`, `incrementExact` and `toIntExact` are the
  usual machine-applicable fixes.
- Suppress with `@SuppressJcheck(code = "J0301", reason = "...")` when wrapping is intended, for
  example a hash or a deliberate 32-bit checksum.
- False positives: mixed-width expressions that already widen to `long` before the operation
  are not reported.
