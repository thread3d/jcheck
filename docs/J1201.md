# J1201 — StressTestFailure

**Tier:** T5 (jcstress) · **Default level:** deny

## Why it matters

A data race is invisible to the compiler and usually invisible to a normal test run: the code
passes on the developer's machine and fails under load. The OpenJDK Concurrency Stress Tests run
the operations under every legal interleaving and report when an outcome the author declared
forbidden actually happens. That is the closest Java gets to Rust's compile-time data-race freedom.

## Failing example

```java
@JCStressTest
@Outcome(id = "1", expect = Expect.ACCEPTABLE, desc = "saw the write")
@Outcome(id = "0", expect = Expect.FORBIDDEN, desc = "race")
@State
public class Racy {
    int x;

    @Actor public void writer() { x = 1; }
    @Actor public void reader(I_Result r) { r.r1 = x; }
}
```

jcstress observes the forbidden state `0` and jcheck reports the test.

## Fixed example

```java
@State
public class Fixed {
    final AtomicInteger x = new AtomicInteger();

    @Actor public void writer() { x.set(1); }
    @Actor public void reader(I_Result r) { r.r1 = x.get(); }
}
```

Or guard both actors with the same lock; the point is that the forbidden outcome becomes
unrepresentable.

## Notes

- `jcheck jcstress` resolves the jcstress jars, compiles {@code @JCStressTest} sources with the
  jcstress annotation processor when no `META-INF/TestList` exists yet, and runs them. Default mode
  is `sanity` (fast); `[tests] jcstress_mode` selects `quick`, `default`, `tough` or `stress`.
- An `Observed forbidden state` is an error; `Observed interesting state` is reported too, because
  an outcome the author marked interesting is usually a bug that is hard to reproduce.
- jcstress needs a multi-core machine to be meaningful; the reported state includes the observed
  value and the author's description.
- This check is opt-in and slow, so it never runs as part of `jcheck check`.
