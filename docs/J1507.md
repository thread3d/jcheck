# J1507 — KotlinRemoveTrailingSemicolon

**Tier:** T5 (rewrite) · **Default level:** note

## Why it matters

Kotlin does not use semicolons as statement terminators, but Java habits and copy-pasted code leave
them behind. `org.openrewrite.kotlin.cleanup.RemoveTrailingSemicolon` removes them, which keeps a
mixed Java/Kotlin codebase visually consistent. This is the first Kotlin recipe jcheck catalogues,
and it exists to show that the rewrite path is not Java-only.

## What the change looks like

```kotlin
// before
fun answer(): Int {
    return 42;
}

// after
fun answer(): Int {
    return 42
}
```

## Notes

- Kotlin sources are found under `src/main/kotlin`, `src/test/kotlin` and the module equivalents, or
  wherever `[project] sources` points; they are never added to the javac compilation, which is Java
  only.
- The runner loads Kotlin support reflectively, so `[fix] rewrite_kotlin = false` still compiles and
  a Kotlin recipe then reports that the frontend is unavailable instead of failing the run.
- Java recipes ignore Kotlin files and vice versa, so both can be listed in `[fix] rewrite_recipes`.
