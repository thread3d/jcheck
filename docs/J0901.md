# J0901 — TestFailure

**Tier:** T5 (test harness) · **Default level:** error

## Why it matters

A failing test is a diagnostic, not a log line. Rendering it through the same model as the
static checks means an agent sees one output format, one code space and one help path whether
the problem was found by the compiler or by a test run. It also makes "the tests pass" a claim
that lives next to the code it is about.

## What it means

The project's test runner produced a JUnit XML report containing a `failure` or `error`. The
primary span points at the first project frame in the stack trace — the line in your code, not
a framework frame — and the notes list the remaining frames with project frames first.

## Failing example

```java
@Test
void totalIsSumOfParts() {
    assertEquals(7, Cart.total(List.of(3, 5)));   // expected 7 but was 8
}
```

## Fixed example

```java
@Test
void totalIsSumOfParts() {
    assertEquals(8, Cart.total(List.of(3, 5)));
}
```

## Notes

- Suppress with `@SuppressJcheck(code = "J0901", reason = "...")` and a real reason.
- A test that is merely flaky should be fixed, not suppressed. Randomized ordering prints its
  seed so a failure can be reproduced.
- If a test times out, the harness attaches a thread dump and reports the deadlock cycle when
  `ThreadMXBean.findDeadlockedThreads` finds one.
