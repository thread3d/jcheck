# J0480 — TryResourceThrowsInterrupted

**Tier:** T2 flow · **Default level:** warn

## Why it matters

When a resource's `close()` can throw `InterruptedException`, try-with-resources has to invent what
to do with an interrupt: the compiler warns because the implicit close site cannot propagate a
checked exception it was not declared to throw. Getting it wrong loses the interrupt and hangs a
shutdown.

## Failing example

```java
try (BlockingResource resource = open()) { // close() throws InterruptedException
    resource.use();
}
```

## Fixed example

```java
BlockingResource resource = open();
try {
    resource.use();
} finally {
    try {
        resource.close();
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
    }
}
```

## Notes

- Restoring the interrupt flag (`Thread.currentThread().interrupt()`) is what keeps a cancellation
  from being swallowed; rethrowing is not possible from the implicit close site.
- The warning appears only for a resource whose `close()` declares `InterruptedException`, which is
  unusual outside blocking queues and channels.
- The related unclosed-resource check is J0801.
