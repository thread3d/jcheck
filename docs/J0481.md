# J0481 — LeaksNotAccessible

**Tier:** T2 flow · **Default level:** warn

## Why it matters

A public API that exposes a type from a package the module does not export is unusable by clients:
they can see the method but cannot name its return or parameter type. The module system warns so the
leak is fixed deliberately rather than discovered by a user who has to guess at `--add-exports`.

## Failing example

```java
module demo {
    exports demo.api;   // demo.api.Service returns demo.internal.Handle
}
```

## Fixed example

```java
module demo {
    exports demo.api;
    exports demo.internal;   // or change the API so it does not expose the internal type
}
```

## Notes

- Exporting is right when the type is genuinely part of the API; narrowing the API is right when it
  was not meant to be.
- The transitive variant is J0482, and the "not exported at all" form is J0471; all three are in the
  `module-access` group.
- The warning comes from `-Xlint:exports`, which the `all` group enables.
