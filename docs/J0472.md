# J0472 — DeprecatedForRemoval

**Tier:** T2 flow · **Default level:** warn

## Why it matters

`@Deprecated(forRemoval = true)` is a stronger promise than a plain deprecation: the API is going
away. Continuing to call it means the code will stop compiling on the next upgrade, so it belongs in
the same list as any other warning rather than being deferred.

## Failing example

```java
Thread.currentThread().stop(); // deprecated for removal, and unsafe
```

## Fixed example

```java
Thread.currentThread().interrupt(); // the supported way to ask a thread to stop
```

## Notes

- This is the `-Xlint:removal` key; plain `@Deprecated` uses the `deprecation` key and is a separate
  catalog row.
- The fix is usually a named replacement in the deprecation note; `@SuppressWarnings("removal")`
  should carry a reason and a linked migration issue.
- The warning appears with the `all` lint group that jcheck enables by default.
