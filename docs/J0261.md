# J0261 — OverrideWeakerAccess

**Tier:** T2 flow · **Default level:** deny

## Why it matters

An override may not reduce visibility: a `protected` method cannot become package-private, and a
`public` one cannot become `protected`. Allowing it would let a subclass hide an operation that
callers of the supertype are entitled to invoke, so the compiler rejects the class.

## Failing example

```java
class Base {
    public void run() {
    }
}

class Sub extends Base {
    @Override
    void run() { // weaker access than public
    }
}
```

## Fixed example

```java
class Sub extends Base {
    @Override
    public void run() {
    }
}
```

## Notes

- Widen the override to at least the overridden method's visibility; the reverse direction
  (`protected` to `public`) is always allowed.
- A `private` method is not inherited, so a same-named method in a subclass is not an override and
  does not need `@Override`.
- The related incompatible-return error is J0260; both are in the `override` group.
