# J0602 — MutationDuringIteration

**Tier:** T3 (jcheck-checks) · **Default level:** deny

## Why it matters

Modifying a collection inside a for-each over that same collection throws
`ConcurrentModificationException` — usually at a later iteration, far from the offending line.
Java only catches this at runtime; this check catches the straightforward static cases so the
bug never reaches a test run.

## Failing example

```java
List<String> names = new ArrayList<>(List.of("ada", " ", "grace"));

for (String name : names) {
    if (name.isBlank()) {
        names.remove(name); // ConcurrentModificationException
    }
}
```

## Fixed example

```java
List<String> names = new ArrayList<>(List.of("ada", " ", "grace"));

names.removeIf(String::isBlank);
```

## Notes

- The usual fixes are `removeIf`, `Map.entrySet().removeIf`, or collecting the changes and
  applying them after the loop. An iterator's own `remove()` is also safe.
- The check matches the same receiver only; mutating a different collection inside the loop is
  not reported.
- Iterating over a defensive copy and mutating the original is safe and is not reported, but
  prefer `removeIf` unless the copy is needed anyway.
- Suppress with `@SuppressJcheck(code = "J0602", reason = "...")` when the receiver is a
  concurrent collection whose iterator is weakly consistent.
