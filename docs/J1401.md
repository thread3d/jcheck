# J1401 — InferFinding

**Tier:** T5 (Infer) · **Default level:** warn

## Why it matters

Infer's Java frontend runs a separation-logic analysis (Pulse) over the source and finds problems a
type checker cannot: a value that is provably null on some path and then dereferenced, a resource
whose ownership is lost, a field written without the lock that guards it. It is a native binary, not
a jar, so it complements the JVM analyzers rather than duplicating their reach.

## Failing example

```java
static int len() {
    String s = null;
    return s.length(); // Infer: `s` could be null and is dereferenced
}
```

## Fixed example

```java
static int len(String s) {
    return s == null ? 0 : s.length();
}
```

## Notes

- `jcheck infer` needs the `infer` binary: set `[bytecode] infer_binary`, export
  `JCHECK_INFER`, or put `infer` on `PATH`. When it is absent the command says so and exits as a
  tool failure, never as a clean T5.
- Infer's results are written under the jcheck cache (`infer -o <cache>/infer/...`), so it never
  drops an `infer-out/` directory into the project.
- The message is Infer's own `qualifier`, which usually names the value, the line it came from and
  the dereference; the `procedure` is attached as a note.
- Scope it to what changed with `--sources`.
- Infer is optional and version-sensitive; the tier line reports T5 as run only when it actually
  ran.
