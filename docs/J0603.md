# J0603 — EscapingMutableInternal

**Tier:** T3 (jcheck-checks) · **Default level:** deny

## Why it matters

Returning or storing an internal mutable array, collection or `Date` lets a caller mutate state
the object believes it owns. This is the ownership gap Rust closes at compile time; in Java it
must be checked. The check flags a mutable internal value that escapes without a defensive copy.

## Failing example

```java
final class Inventory {
    private final List<String> items;

    Inventory(List<String> items) {
        this.items = items; // the caller keeps a reference
    }

    List<String> items() {
        return items; // the caller can now mutate our state
    }
}
```

## Fixed example

```java
final class Inventory {
    private final List<String> items;

    Inventory(List<String> items) {
        this.items = List.copyOf(items); // defensive copy at the boundary
    }

    List<String> items() {
        return items; // safe: the list is immutable
    }
}
```

## Notes

- The usual fixes are `List.copyOf` / `Set.copyOf` / `Map.copyOf` for collections and
  `clone()` for arrays. Do not return `Collections.unmodifiableList(items)` while `items` is
  still mutable elsewhere.
- Storing an argument by reference is the same bug as returning a field by reference; both are
  reported.
- Suppress with `@SuppressJcheck(code = "J0603", reason = "...")` for a deliberately shared,
  documented buffer whose mutability is part of the contract.
