# J0466 — PossibleFallThrough

**Tier:** T2 flow · **Default level:** warn

## Why it matters

A `switch` case that reaches the next case without a `break`, `return` or `throw` is almost always a
missing statement rather than a deliberate fall-through. When it is deliberate, saying so in a
comment is what separates intent from a bug for the next reader.

## Failing example

```java
switch (day) {
    case MONDAY:
        startWeek();
    case TUESDAY:   // control falls through from MONDAY
        work();
        break;
}
```

## Fixed example

```java
switch (day) {
    case MONDAY:
        startWeek();
        break;
    case TUESDAY:
        work();
        break;
}
```

## Notes

- A deliberate fall-through is annotated with a comment such as `// fall through`, which is the
  documented way to silence this lint.
- Switch *expressions* and arrow-form cases never fall through, so they are not reported.
- This is the JDK 21+ spelling of the older `fallthrough` key (J0407); both map to the same group.
