# J0260 — OverrideIncompatibleReturn

**Tier:** T2 flow · **Default level:** deny

## Why it matters

An override must be return-type substitutable for the method it replaces: the same type, or a
subtype (a covariant return). When it is not, callers that go through the supertype get a value of
the wrong type and the compiler refuses the class. The error is often the first sign that two
overloads differ only in return type, which Java does not allow.

## Failing example

```java
class Base {
    Object value() {
        return "x";
    }
}

class Sub extends Base {
    @Override
    String value() {
        return 1; // not a String
    }
}
```

## Fixed example

```java
class Sub extends Base {
    @Override
    String value() {
        return "1";
    }
}
```

## Notes

- Covariant returns are legal: `CharSequence value()` overriding `Object value()` compiles.
- Two methods that differ only in return type are not overloads; rename one instead.
- The related weaker-access error is J0261; both are in the `override` group.
