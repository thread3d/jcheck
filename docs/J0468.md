# J0468 — ThisEscape

**Tier:** T2 flow · **Default level:** warn

## Why it matters

A constructor that calls an overridable method, registers a listener, or otherwise publishes `this`
lets code run against a partially built object. A subclass override then sees fields that are still
zero or null, and a listener can be invoked on another thread before construction finishes. The
JDK 21+ `-Xlint:this-escape` lint names the places this happens.

## Failing example

```java
class Base {
    Base() {
        init(); // overridable: a subclass override runs before the subclass fields are set
    }

    void init() {
    }
}
```

## Fixed example

```java
class Base {
    Base() {
        // no overridable calls and no publication from the constructor
    }

    void init() {
    }
}
```

## Notes

- The usual fixes are to make the called method `private` or `final`, to move the work into a
  factory method that runs after construction, or to pass the dependencies in and initialise in an
  `init` the caller invokes.
- Registering a listener, starting a thread, or storing `this` in a static or shared field from a
  constructor are the other common escapes.
- The lint exists from JDK 21; jcheck catalogues both the summary key and the location key it
  emits, so a JDK 25 run is fully catalogued too.
