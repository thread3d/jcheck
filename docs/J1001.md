# J1001 — UnclosedExecutorOrThread

**Tier:** T3 (jcheck-checks) · **Default level:** deny

## Why it matters

An `ExecutorService` or a raw `Thread` carries no type-level close obligation, so a forgotten
`shutdown()` keeps non-daemon threads alive: a hanging JVM in production and a leaked thread in
tests. This check requires a visible shutdown path on every path, the same guarantee
try-with-resources gives for `AutoCloseable`.

## Failing example

```java
void runJobs(List<Runnable> jobs) {
    ExecutorService pool = Executors.newFixedThreadPool(4);
    jobs.forEach(pool::submit); // the pool is never shut down
}
```

## Fixed example

```java
void runJobs(List<Runnable> jobs) throws InterruptedException {
    ExecutorService pool = Executors.newFixedThreadPool(4);
    try {
        jobs.forEach(pool::submit);
    } finally {
        pool.shutdown();
        pool.awaitTermination(1, TimeUnit.MINUTES);
    }
}
```

## Notes

- A `shutdown()` plus `awaitTermination` in a `finally` block is the minimum. Prefer an injected,
  long-lived executor that outlives the request and is closed once at the edge of the program.
- Raw `new Thread(...).start()` is reported unless the method also joins or interrupts the
  thread on every path.
- `Executors.newCachedThreadPool` and other unbounded pools are additionally discouraged by the
  concurrency policy; bound the queue or the thread count.
- For `AutoCloseable` resources (streams, readers, connections) use J0801 instead.
