# J0488 — ObsoleteOptionSuppression

**Tier:** T2 (flow) · **Default level:** warn

## Why it matters

javac pairs its obsolete-release warnings with one line of advice: silence the group with
`-Xlint:-options`. jcheck keeps that line as its own diagnostic instead of folding it into a note,
because it is a decision the reader has to make — raise the floor (J0486/J0487) or deliberately
silence the lint. A silenced warning is not the same as a raised floor, and the report should say
so explicitly rather than hiding the choice in a note.

## Failing example

Any run whose release floor the JDK has deprecated:

```text
warning: [options] To suppress warnings about obsolete options, use -Xlint:-options.
```

## Fixed example

Either raise the floor, which removes all three warnings:

```bash
javac --release 17 ...
```

or silence the lint deliberately, which keeps the floor and accepts the warning:

```bash
javac --release 8 -Xlint:-options ...
```

## Notes

- This is the only one of the three obsolete-release diagnostics that is purely advisory: the
  other two (J0486, J0487) name a value that will actually stop working.
- In `strict` a warning becomes an error, so this line fails the run by itself. That is the point
  of strict — but it also means a pinned old floor needs an explicit policy decision
  (`lenient`, a per-code override, or `-Xlint:-options`).
- jcheck's own analyzer runs pass `--release` from the project's declared floor, so this warning
  is a statement about the project's configuration, not about jcheck's choice of flags.
