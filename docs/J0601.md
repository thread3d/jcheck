# J0601 — SharedMutableWithoutGuard

**Tier:** T3 (jcheck-checks) · **Default level:** deny in `@ThreadSafe`

## Why it matters

A mutable field on a `@ThreadSafe` class that is read or written from more than one thread is a
data race unless every access holds the same lock. Java does not check this, so `@ThreadSafe`
becomes an unverified promise. This check holds the class to it, mirroring Rust's `Send`/`Sync`
discipline.

## Failing example

```java
@ThreadSafe
final class Counter {
    private int count; // shared mutable state with no @GuardedBy

    void increment() {
        count++;
    }
}
```

## Fixed example

```java
@ThreadSafe
final class Counter {
    @GuardedBy("this")
    private int count;

    synchronized void increment() {
        count++;
    }
}
```

## Notes

- A `final` field of an immutable type needs no guard, and a field whose accesses all occur
  during construction and are never mutated afterwards is not reported.
- Error Prone `GuardedBy` verifies that the lock named in `@GuardedBy` is actually held; this
  check only requires the annotation where a guard is needed.
- Prefer `AtomicInteger`, `AtomicReference` or a concurrent collection over a lock when the
  operation is a single atomic update.
- Suppress with `@SuppressJcheck(code = "J0601", reason = "...")` only when the field is
  genuinely single-threaded despite the class annotation.
