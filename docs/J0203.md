# J0203 — MissingReturnStatement

**Tier:** T2 (flow) · **Default level:** error

## Why it matters

A non-void method must return a value on every path the compiler can reach. This is definite
assignment and reachability, not a style rule: falling off the end of such a method is a compile
error, and if it were tolerated the caller would receive an unspecified result.

## Failing example

```java
int sign(int value) {
    if (value < 0) {
        return -1;
    }
    if (value > 0) {
        return 1;
    }
    // value == 0 falls off the end of the method
}
```

## Fixed example

```java
int sign(int value) {
    if (value < 0) {
        return -1;
    }
    if (value > 0) {
        return 1;
    }
    return 0;
}
```

## Notes

- Add the final `return`, or end with a `throw` when the path is genuinely impossible. With
  sealed types, an exhaustive switch expression is often cleaner than trailing returns.
- Do not paper over the gap with a sentinel value such as `-1` or `0` unless that value is part
  of the method's contract; prefer `OptionalInt` or a documented exception.
- Not to be confused with unreachable code (J0247), which is the opposite mistake.
