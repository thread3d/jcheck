# J0483 — OverrideUncheckedReturn

**Tier:** T2 flow · **Default level:** warn

## Why it matters

Overriding a method with an unchecked return type means the caller's inferred type argument is not
verified: the override can return anything and the cast the caller inserts will fail at a distance.
The compiler warns at the override so the mismatch is visible where it is introduced.

## Failing example

```java
class Base {
    <T> List<T> values() {
        return List.of();
    }
}

class Sub extends Base {
    @Override
    List values() { // unchecked override: the type argument is erased
        return List.of(1, 2);
    }
}
```

## Fixed example

```java
class Sub extends Base {
    @Override
    <T> List<T> values() {
        return List.of();
    }
}
```

## Notes

- Keep the method generic in the override; erasing the type argument in the subclass is what makes
  the return unchecked.
- The related unchecked-conversion warning is J0419 and the unchecked-invocation one is J0474; all
  are in the `unchecked` group.
- If the override genuinely cannot be generic, `@SuppressWarnings("unchecked")` with a reason is the
  documented escape.
