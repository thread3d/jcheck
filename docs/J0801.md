# J0801 — UnclosedResource

**Tier:** T3 (jcheck-checks) · **Default level:** deny

## Why it matters

Every `AutoCloseable` — streams, readers, JDBC objects, `HttpClient`s, the `Stream` returned by
`Files.lines` or `Files.walk` — must be closed on all paths. A leak exhausts file descriptors or
connections long before anyone notices, and it fails only under load.

## Failing example

```java
static String read(Path path) throws IOException {
    BufferedReader reader = Files.newBufferedReader(path);
    return reader.readLine(); // the reader is never closed
}
```

## Fixed example

```java
static String read(Path path) throws IOException {
    try (BufferedReader reader = Files.newBufferedReader(path)) {
        return reader.readLine();
    }
}
```

## Notes

- Prefer try-with-resources. Error Prone `MustBeClosedChecker`, javac `-Xlint:try` and the
  Checker Framework Resource Leak Checker report the same class of problem and are merged into
  this code's group rather than shown twice.
- Ownership can be handed off: returning a stream, or passing it to an `@Owning` parameter, is
  not a leak.
- Streams from `Files.lines`/`Files.walk` must be closed even though the call looks like a plain
  collection operation.
- For executors and threads, which have no `close()` obligation, see J1001.
