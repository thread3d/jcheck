# J0484 — RestrictedTypeName

**Tier:** T2 (flow) · **Default level:** warn

## Why it matters

`var`, `yield`, `record`, `sealed` and `permits` became *restricted type names* as the language
evolved: they may still be used as identifiers, but not as type names, in releases that reserve
them. A project whose release floor is older than that reservation still compiles code which
uses the word as a type, and this warning is javac telling you the code will stop compiling when
the floor is raised. It is a forward-compatibility check, not a complaint about the current run.

## Failing example

Compiled at a release floor below 10, where `var` is still an ordinary type name:

```java
public final class Legacy {
    static int value() {
        var x = 1; // "var" here is a type name, not inference
        return x;
    }
}
```

At `-source 8` javac reports the warning (and a `cannot find symbol: class var` error) because
the release does not yet special-case `var`.

## Fixed example

```java
public final class Legacy {
    static int value() {
        int x = 1; // name the type: works on every release
        return x;
    }
}
```

## Notes

- Renaming the type is the fix that survives a floor bump; spelling out the type as above also
  removes the companion `cannot find symbol`.
- Once the target release actually reserves the name, javac reports a hard error instead of this
  warning, so a clean run at an old floor is not a promise about a newer one.
- The companion code J0485 covers the `may become a restricted type name in a future release`
  variant, which fires for names that are not yet reserved at any release.
