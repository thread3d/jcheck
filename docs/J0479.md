# J0479 — UncheckedGenericArrayCreation

**Tier:** T2 flow · **Default level:** warn

## Why it matters

Creating a generic array — most often the implicit array behind a varargs parameter — is unsound:
the array's runtime component type is erased, so a caller can store a value of the wrong type in it
and the failure surfaces later as a `ClassCastException` somewhere else. This is the warning the
compiler emits at the declaration site.

## Failing example

```java
static <T> List<T> listOf(T... values) {
    Object[] array = values; // the array is really Object[], not T[]
    array[0] = 42;
    return Arrays.asList(values);
}
```

## Fixed example

```java
@SafeVarargs
static <T> List<T> listOf(T... values) {
    return List.of(values);
}
```

## Notes

- If the method does not write into the array and does not leak it, `@SafeVarargs` states that. It
  is allowed only on static, final or private methods and on constructors.
- The related warnings are J0413 (heap pollution from a parameterized vararg type) and J0465
  (unsafe use of a varargs parameter); all three share the `unchecked-varargs` group.
- A real generic array is created with `Array.newInstance(componentType, length)`, never with a cast.
