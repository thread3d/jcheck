# J0131 — FeatureNotSupportedAtRelease

**Tier:** T0 (syntax) · **Default level:** error

## Why it matters

A language feature is accepted only from the release that introduced it, and javac rejects the
construct outright when the project's release floor is lower. The message names both the feature
and the release it needs, so the fix is a build-configuration change rather than a rewrite:
either raise `--release` (or `-source`) to a release that has the feature, or stop using it.

This is a T0 diagnostic even though the file is otherwise well-formed: the parser refuses the
construct before type-checking starts, so nothing above T0 can run.

## Failing example

```java
public final class Levels {
    static String text() {
        return """
            text blocks are Java 15
            """;
    }
}
```

Compiled with a release floor below 15:

```text
error: text blocks are not supported in -source 8
  (use -source 15 or higher to enable text blocks)
```

## Fixed example

```java
public final class Levels {
    static String text() {
        return "text blocks are Java 15\n";
    }
}
```

Or keep the feature and raise the floor (`--release 15`, or `maven.compiler.release=15`).

## Notes

- The feature list in the message is authoritative: it names every construct the release is
  missing, so one diagnostic can stand for several edits.
- Raising `--release` changes the *API* the compiler checks against as well as the syntax. A
  project on a modern JDK but an old floor will also see J04xx warnings about the obsolete
  release, which are the same signal from the options side.
- jcheck reports this at the release the project declares, so a file that compiles in an IDE set
  to a newer language level still fails here.
