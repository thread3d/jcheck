# J1102 — UncoveredLine

**Tier:** T5 (coverage) · **Default level:** warn

## Why it matters

Passing tests say nothing about the lines they never executed. A branch nobody calls, an error path
that only fires in production, a `catch` that has never run: coverage names them. jcheck reports
them as diagnostics rather than a percentage so they land in the same list as everything else and an
agent can act on the specific line.

## Failing example

```java
static int discount(int price) {
    if (price < 0) {
        throw new IllegalArgumentException("negative price"); // no test ever takes this path
    }
    return price;
}
```

```java
@Test
void applies() {
    assertEquals(10, discount(10)); // the guard is never executed
}
```

JaCoCo reports the `throw` line as uncovered, and jcheck renders it as `J1102`.

## Fixed example

```java
@Test
void rejectsNegative() {
    assertThrows(IllegalArgumentException.class, () -> discount(-1));
}
```

## Notes

- Coverage needs the tests to run under the JaCoCo agent: `jcheck test --launcher --coverage`, or
  `[tests] coverage = true`. It only applies to the console-launcher path, because the agent has to
  be added to the test JVM.
- A line with no executed instructions is reported as "not covered by any test"; a line with some
  instructions executed and some not is reported as "only partially covered", which is usually a
  branch that needs a second case.
- Coverage is a map, not a goal: it says which lines were visited, never whether the assertions on
  them mean anything. `jcheck mutate` (`J1101`) is what answers that.
- Lines in generated or third-party code are not reported; only the project's own production sources
  are.
