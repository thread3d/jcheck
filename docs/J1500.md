# J1500 — OpenRewriteRecipe

**Tier:** T5 (rewrite) · **Default level:** note

## Why it matters

`jcheck rewrite` changes source, so the change itself has to be reviewable. Every applied recipe is
reported with a stable code, the file it touched and the recipe that did it, which means a rewrite
lands in the same diagnostic list as everything else instead of as an unexplained diff.

## What it means

This is the fallback code for a recipe that has no curated row yet. It is not a defect: it is a
record that a recipe ran. Review the change and, if the recipe is used often, add a catalog row so
future runs name it precisely.

## Notes

- The curated recipes are J1501 (MissingOverrideAnnotation), J1502 (FinalizeLocalVariables) and
  J1503 (UseTryWithResources); this code covers the rest.
- `jcheck rewrite` exits clean: applying a recipe is not a diagnostic at error level, and
  `jcheck fix` will only keep a rewrite whose re-check did not get worse.
- Recipes come from `rewrite-static-analysis`; the list is `[fix] rewrite_recipes`.
