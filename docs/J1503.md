# J1503 — UseTryWithResources

**Tier:** T5 (rewrite) · **Default level:** note

## Why it matters

OpenRewrite's `org.openrewrite.staticanalysis.UseTryWithResources` rewrites a manual
`try { ... } finally { resource.close(); }` into try-with-resources. That removes the possibility of
a missed close on an exception path and shortens the code, which is exactly what J0801 warns about
when it is not done.

## What the change looks like

```java
// before
BufferedReader reader = Files.newBufferedReader(path);
try {
    return reader.readLine();
} finally {
    reader.close();
}

// after
try (BufferedReader reader = Files.newBufferedReader(path)) {
    return reader.readLine();
}
```

## Notes

- The recipe only rewrites a close that is unconditional and at the end of the `finally`; a close
  that depends on the outcome is left alone.
- It complements J0801: the check finds the resource that is never closed, the recipe fixes the ones
  that are closed by hand.
- jcheck never applies a rewrite without re-checking; a rewrite that introduces an error is reverted
  and reported.
