# J0701 — UnsafeOutsideUnsafe

**Tier:** T3 (jcheck-checks) · **Default level:** deny

## Why it matters

Some operations cannot be made safe by types: `sun.misc.Unsafe`, `jdk.internal.*`, reflective
`setAccessible`, JNI and FFM downcalls, `Thread.stop`, native memory APIs and deserialization of
untrusted types. Rust marks such a boundary with `unsafe`; this check requires the same explicit
boundary in Java, with a reason attached to the annotation.

## Failing example

```java
Method m = String.class.getDeclaredMethod("value");
m.setAccessible(true); // no @Unsafe region in sight
byte[] raw = (byte[]) m.invoke(text);
```

## Fixed example

```java
@Unsafe(reason = "reads the compact String value for a zero-copy codec; layout verified on JDK 21")
static byte[] rawValue(String text) throws ReflectiveOperationException {
    Method m = String.class.getDeclaredMethod("value");
    m.setAccessible(true);
    return (byte[]) m.invoke(text);
}
```

## Notes

- The region is a method or a class annotated `@Unsafe(reason = "...")`; the reason must be
  non-empty, so the exception is greppable and reviewable.
- Prefer `VarHandle` and `MethodHandles.Lookup.privateLookupIn` over `setAccessible` where they
  suffice; the check no longer applies once plain reflection is enough.
- A blanket `--add-opens` is not a substitute: the reflective access itself is still flagged.
- Untrusted deserialization and `Thread.stop` are in scope too, not just memory APIs.
