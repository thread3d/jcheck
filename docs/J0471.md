# J0471 — LeaksNotAccessibleUnexported

**Tier:** T2 flow · **Default level:** warn

## Why it matters

When a public API exposes a type from a package the module does not export, callers outside the
module cannot name it. The module system warns about the leak so the API surface can be fixed
deliberately instead of failing later with an `--add-exports` the user has to discover.

## Failing example

```java
module demo {
    exports demo.api;          // demo.api.Customer has a method returning demo.internal.Flag
}
```

## Fixed example

```java
module demo {
    exports demo.api;
    exports demo.internal;     // or change the API so it does not use the internal type
}
```

## Notes

- Exporting the package is the fix when the type really is part of the API; otherwise narrow the API
  so the internal type is not returned or accepted.
- `--add-exports` in a build file is a workaround for a caller, not a fix for the module that leaks.
- The warning only appears when compiling with `-Xlint:exports`, which the `all` lint group enables.
