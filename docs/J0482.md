# J0482 — LeaksNotAccessibleNotRequiredTransitive

**Tier:** T2 flow · **Default level:** warn

## Why it matters

This is the transitive form of J0481: a type leaks through a module that is required but not
`requires transitive`, so a client that depends only on this module can see the type in a signature
but has no read edge to it. The API looks public and is not usable, which is exactly the kind of
breakage that only shows up at a client's compile time.

## Failing example

```java
module demo {
    requires internal.util;             // not transitive
    exports demo.api;                   // demo.api.Service returns internal.util.Handle
}
```

## Fixed example

```java
module demo {
    requires transitive internal.util;  // clients that use demo.api also read internal.util
    exports demo.api;
}
```

## Notes

- `requires transitive` is the right answer only when the leaked type is part of the promised API;
  otherwise change the signature.
- This and J0481 are in the `module-access` group, so one API mistake is not reported as two
  unrelated findings.
- The warning comes from `-Xlint:exports`; it needs a module-aware build to appear at all.
