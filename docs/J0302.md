# J0302 — LossyCast

**Tier:** T3 (jcheck-checks) · **Default level:** deny

## Why it matters

A narrowing primitive cast — `(int)` on a `long`, `(short)` on an `int`, `(byte)` on a `char` —
truncates silently. Rust makes every conversion explicit and fallible; Java's cast hides the
loss behind ordinary syntax. This check forces a checked conversion or a range check.

## Failing example

```java
long total = 5_000_000_000L;
int count = (int) total; // wraps to 705032704
```

## Fixed example

```java
long total = 5_000_000_000L;
int count = Math.toIntExact(total); // throws ArithmeticException instead of truncating
```

## Notes

- Covered: `long` to `int`, `int` to `short`/`byte`/`char`, `double`/`float` to `int`/`long`,
  and the equivalent compound-assignment narrowing.
- Use `Math.toIntExact`/`toIntExact` where the value must fit, or an explicit range check that
  throws with a useful message. A bare cast plus a comment is not accepted.
- Suppress with `@SuppressJcheck(code = "J0302", reason = "...")` for deliberate truncation such
  as a hash fold; the reason makes the intent reviewable.
- Widening casts and casts between same-width types are not reported.
