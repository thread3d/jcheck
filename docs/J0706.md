# J0706 — LocalCanBeFinal

**Tier:** T3 (jcheck-checks) · **Default level:** warn

## Why it matters

A local variable that is assigned once and never reassigned tells the reader it cannot change.
Making it `final` records that fact and lets the compiler reject a later accidental write, which
is the same immutability-by-default discipline the strict profile applies to fields.

## Failing example

```java
final class Checkout {
    void print(int price, int tax) {
        int total = price + tax;
        applyDiscount(total);
        System.out.println(total);
    }

    void applyDiscount(int amount) {
    }
}
```

## Fixed example

```java
final class Checkout {
    void print(int price, int tax) {
        final int total = price + tax;
        applyDiscount(total);
        System.out.println(total);
    }

    void applyDiscount(int amount) {
    }
}
```

## Notes

- Reported only when the variable is assigned exactly once and never reassigned; a variable
  reassigned on any path is left alone.
- Pattern variables, try-with-resources variables and enhanced-for loop variables are already
  effectively final and are not reported.
- Suppress with `@SuppressJcheck(code = "J0706", reason = "...")` only when `final` genuinely
  hurts readability, for example a long reassignment-free builder chain.
- This is a warning, not an error: it does not block a compile even in the strict profile.
