# J0487 — ObsoleteTargetRelease

**Tier:** T2 (flow) · **Default level:** warn

## Why it matters

`target value 8 is obsolete and will be removed in a future release` is the bytecode half of the
same problem as J0486: the compiler will stop producing class files for that target release.
`-source` and `-target` also have to agree, so the pair is adjusted together — in jcheck and
Maven/Gradle both are set by a single release floor, and hand-edited `-source`/`-target` pairs are
where they usually drift apart.

## Failing example

```bash
javac -source 8 -target 8 ...
```

```text
warning: [options] target value 8 is obsolete and will be removed in a future release
```

As with J0486, `--release 8` on a modern JDK produces the same pair of warnings.

## Fixed example

```bash
javac --release 17 ...
```

One flag, one release: `--release` sets source, target and the API surface together, so they
cannot disagree.

## Notes

- Prefer `--release` over `-source`/`-target`; it is the form that stays consistent and the only
  one that also pins the platform API.
- Companion codes: J0486 for the source value, J0488 for javac's suppression hint.
- A library that ships a lower floor can legitimately keep it — see J0486's notes on
  `-Xlint:-options`.
