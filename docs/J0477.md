# J0477 — RedundantTrustMeAnnotation

**Tier:** T2 flow · **Default level:** warn

## Why it matters

`@TrustMe` (from the `@SuppressWarnings`-style varargs family) promises the compiler that a generic
varargs method is safe. Where the compiler already trusts the method — because it is `final`,
`static`, `private` or a constructor — the annotation adds nothing and hides the real reason the
method is safe. The lint names the redundant promise so the code says only what is true.

## Failing example

```java
@TrustMe
static <T> List<T> of(T... values) {
    return Arrays.asList(values);
}
```

## Fixed example

```java
@SafeVarargs
static <T> List<T> of(T... values) {
    return Arrays.asList(values);
}
```

## Notes

- Prefer `@SafeVarargs`, which is the standard annotation and is checked; `@TrustMe` is for the
  cases the compiler cannot verify.
- The warning appears only when the redundant annotation is on a method the compiler already
  trusts.
- The related unchecked-varargs warnings are J0413 and J0465.
