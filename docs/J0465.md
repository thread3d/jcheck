# J0465 — UnsafeVarargs

**Tier:** T2 flow · **Default level:** warn

## Why it matters

A generic method with a varargs parameter has an array whose element type is erased, so the caller
can smuggle a value of the wrong type into it and the failure surfaces later, somewhere else, as a
`ClassCastException`. `@SafeVarargs` is the promise that the method does not do that, and it is the
only way to say so to both the compiler and the next reader.

## Failing example

```java
static <T> List<T> of(T... values) {
    return Arrays.asList(values); // possible heap pollution from a parameterized vararg type
}
```

## Fixed example

```java
@SafeVarargs
static <T> List<T> of(T... values) {
    return Arrays.asList(values);
}
```

## Notes

- `@SafeVarargs` is allowed only on static, final or private methods, and on constructors, because
  otherwise a subclass could override the method with an unsafe one.
- If the method genuinely is not safe, pass an explicit array (`of(new String[]{...})`) or take a
  `List<T>` instead.
- This is the varargs-specific sibling of J0413; both are in the `unchecked-varargs` group so they
  are not reported twice for the same declaration.
