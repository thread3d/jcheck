# J0705 — MutableStaticState

**Tier:** T3 (jcheck-checks) · **Default level:** deny in strict

## Why it matters

Mutable static fields are global state: they make tests order-dependent, initialization
non-deterministic, and publication across threads unsafe. Rust has no safe mutable global, and
Java should make every deliberate exception visible rather than ambient.

## Failing example

```java
final class Registry {
    static Map<String, Service> SERVICES = new HashMap<>(); // mutable global

    static void register(String name, Service service) {
        SERVICES.put(name, service);
    }
}
```

## Fixed example

```java
final class Registry {
    private static final Map<String, Service> SERVICES = new ConcurrentHashMap<>();
    private Registry() {
    }

    static void register(String name, Service service) {
        SERVICES.put(name, service);
    }

    static Service service(String name) {
        return SERVICES.get(name);
    }
}
```

## Notes

- `static final` is not automatically safe: a `final` field holding a mutable collection still
  counts, because its contents can change. Prefer immutable or concurrent collections and a
  narrow, explicit API.
- Constants — `static final` primitives, `String` and other immutable values — are not reported.
- A deliberate global cache, counter or registry is allowed by an allow-list annotation, or by a
  documented suppression: `@SuppressJcheck(code = "J0705", reason = "...")`.
