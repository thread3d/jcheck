# J0256 — StaticImportNotFromType

**Tier:** T1 (symbols and types) · **Default level:** error

## Why it matters

A static import names *one static member of one class or interface*. When the qualifier resolves
to a package, or to a field, or does not resolve at all, there is no member to import and javac
rejects the import. The qualifier is usually a package prefix the author expected to be a type,
which is why the diagnostic appears as a second error next to `package demo does not exist`.

A nested class *is* a static member, so `import static java.util.Map.Entry;` is legal. What is
not legal is reaching *through* a member: a field's members are not static members of the class.

## Failing example

```java
import static java.lang.System.out.println; // System.out is a field, not a type
import static demo.Missing.member;          // demo is a package, not a type

public final class Imports {
    void run() {
        println("hi");
    }
}
```

## Fixed example

```java
import static java.lang.System.out;

public final class Imports {
    void run() {
        out.println("hi");
    }
}
```

## Notes

- Import the declaring type and qualify the member, or import the type (non-static) and call
  `Type.member`.
- Because the same line can also produce an unresolved-package error (J0207/J0209), expect this
  code alongside it rather than as the only finding.
- A static import has no runtime cost; the fix is purely about naming a real member.
