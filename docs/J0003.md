# J0003 — SuppressionNeedsReason

**Tier:** T2 (policy) · **Default level:** deny

## Why it matters

A suppression is a promise that the diagnostic is wrong here. Without a written reason that
promise is unauditable: a reviewer cannot tell a deliberate exception from a stale workaround,
and an agent cannot tell whether the code still deserves it. jcheck accepts a suppression only
when it carries a non-empty reason, so every one can be reviewed and expired.

## Failing example

```java
final class Names {
    @SuppressWarnings("NullAway")
    String display(User user) {
        return user.name().trim();
    }
}
```

## Fixed example

```java
final class Names {
    @SuppressJcheck(code = "J0503", reason = "User.name() is non-null by the JSpecify contract")
    String display(User user) {
        return user.name().trim();
    }
}
```

## Notes

- Supported forms are `@SuppressJcheck(code = "...", reason = "...")` and
  `@Unsafe(reason = "...")`; a bare `@SuppressWarnings` with no reason is rejected.
- `jcheck check --report-suppressions` lists every suppression and its reason so review can
  audit the whole set.
- There is no blanket "disable all"; suppress one code at a time.
- The reason is free text, so write what makes the diagnostic inapplicable, not "known issue".
